Form Exploration Engine

One generic pipeline that logs into any of this platform's environments, discovers whatever referral forms exist that day, fills every field it finds, and reports what happened — with no form names or environment URLs hardcoded anywhere in the code.

Why this works everywhere

Every cross-environment lookup reads real DOM structure (a class name, a data-url attribute) instead of matching rendered English text, which differs by environment and even by form. The one time text-matching was tried for form discovery, a form with no description line got silently skipped — the fix switched to structure and that whole class of bug stopped recurring.

How a new form gets covered

It doesn't need new code. explore-all-forms.spec.ts reads whatever the popup currently lists and runs the same engine against each one. A form added to an environment tomorrow is picked up on the next run automatically.

How a new environment gets covered

Point BASE_URL, BROKERAGE_EMAIL and BROKERAGE_PASSWORD at it and run the same test. Proven against three real environments (Next, Surrey, Richmond & Wandsworth) with zero environment-specific code paths.

Every fix is evidence-driven

Each hardening in the engine — retrying past a toast notification, re-opening a dropdown that closed early, recovering from a cascading reveal — was written against a real failure captured from a live run, verified, then committed. Nothing here was guessed blind.
